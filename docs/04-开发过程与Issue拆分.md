## 三、踩坑记录

这一节是给「也用 MoonBit 做项目的人」看的。每一条都是实际编译器报错逼出来的。

### 3.1 工具链安装（无管理员权限）

官方安装脚本走不通，改为手动下载解压：

```
https://cli.moonbitlang.com/binaries/latest/moonbit-windows-x86_64.zip   → ~/.moon/bin
https://cli.moonbitlang.com/cores/core-latest.zip                       → ~/.moon/lib
```

**关键一步**：标准库需要为 JS 后端预编译一次，否则 `moon run --target js` 会报 `Sys_error: json.mi not found`。

```bash
cd ~/.moon/lib/core && moon bundle --target js
```

这一步在官方文档里不显眼，但**不做的话 JS 后端完全跑不起来**。

### 3.2 MoonBit 语法细节（都是编译器教会的）

| 写法 | 报错 / 问题 | 正确写法 |
| --- | --- | --- |
| `let mut x : Int` | 局部变量不支持 `mut` 声明 | 用 `@ref.Ref`，或改为累加式的 `let mut` 在函数作用域内的惯用形式 |
| `0..5` | 区间语法变更 | `0..<5` |
| `s.trim_space()` | 方法名变更 | `s.trim()` |
| `view.to_string()` | `StringView` 无此方法 | `view.to_owned()` |
| `acos(x)` | 不在预置作用域 | `import math` 后 `@math.acos(x)`；且**必须先 clamp 到 [-1, 1]**，否则返回 NaN |
| `not(x)` | 已废弃 | `!(x)` |
| `token.substring(start=5)` | 已废弃 | `token[5:]` |
| `priv fn` 在包顶层 | 包级函数不支持 `priv` | 直接写 `fn`（包级默认即包内可见） |
| `enum` 用 `!=` 比较 | 需要 `Eq` | `derive(Eq)` 后用 `==` |
| 多行字符串字面量裸写在顶层 | `#|...` 只在 `let` / FFI / **括号内**合法 | 把函数体用 `()` 包起来 |
| 测试里 `fail(...)` | 需要异常声明 | 函数签名加 `raise` |
| `counter.update(...)` 返回值被忽略 | 编译警告/报错 | `let _ = counter.update(...)` |
| `assert_eq(option, None)` | 类型推断不出 | `assert_true(x is None)` |
| 浮点相等断言 | `Some(0.792) != Some(0.791999...)` | 用 `almost_equal` 比较，或在指标层就做取整 |

### 3.3 JS 后端互操作

- **`moon.pkg` 的 `options(link: {"js": {...}})`** 是唯一能让编译产物变成可用 ES Module 的地方；`format: "esm"` + 显式 `exports` 列表。
- **`pub extern "js" fn` 无法直接作为 ESM 导出名**。解决办法：把 FFI 函数改名为 `speak_impl` / `now_ms_impl`（`extern "js"`，非 pub），再用普通的 `pub fn api_speak` / `pub fn api_now_ms` 包一层。
- **增量构建的坑**：改了 `api.mbt` 之后 `moon build --target js` 报「no work to do」，产物里却没有新函数。原因是**构建模式搞错了**：`moon build --target js` 默认产出 **debug**，产物在 `_build/js/debug/...`；而页面引用的是 **release** 路径：

  ```bash
  moon build --release --target js     # 产物：_build/js/release/build/src/bridge/bridge.js
  ```

  两个模式各有自己的缓存与产物目录，混着看会出现「明明改了却没生效」的假象。判断依据是产物路径里有没有 `release`。
- **跨包类型引用**：`JsonObject` 在引擎包里是 `pub struct`，但桥接层需要构造它。解决办法是在引擎里加一个 `pub fn json_object() -> JsonObject` 工厂函数，桥接层用 `@engine.json_object()`。
- **结构体是值语义**：`session_counters[i]` 取出的是**副本**，必须「取出 → 推进 → 写回」三步：
  ```moonbit
  let counter = session_counters[index]
  let snapshot = counter.update(frame, now_ms)
  session_counters[index] = counter
  ```
  这跟 JS/Java 的引用语义直觉相反，忽略它会得到一个「永远数不到次数」的诡异 bug。

### 3.4 领域建模上的两个非技术坑

1. **健康宣称的措辞**：最初写的是「安全版本」，被自己的评审流程否掉——因为我们**没有做过任何临床验证**。「安全」是一个需要证据的词。全文改为「低冲击变式」「降低关节负荷」。这个改动同时影响了规则表的 `note`、指导语模板、界面文案和 README。细节见 `docs/06-安全边界与免责声明.md`。
2. **正前方看不到屈膝深度**：最初深蹲用 `knee_left` / `knee_right` 做判据，实测发现正面机位下这两个角度的读数几乎不随下蹲变化（3D 姿态被投影到 2D 平面后深度信息丢失）。改用 `hip_height_ratio` 才稳定。这是一次**被观测数据推翻的设计**，也是为什么指标表里特意写明了这个取舍。
