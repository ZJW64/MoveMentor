# MoveMentor · 动译师 —— 一页项目说明

> 提交物：一页项目说明（申报 / 验收用）
> 仓库：`hackathon/movementor` ｜ 许可：Apache-2.0 ｜ 参赛期：2026-09-18 ~ 2026-09-24

---

## 一句话

**用 MoonBit 写成的「动作安全翻译引擎」：输入一个年轻人在做的健身动作和目标人群，输出这个人能做的低冲击变式、计数规则和指导语。**

## 要解决的问题

一位膝痛老人或轮椅使用者看到「跟练开合跳」的视频时，处境是没有可执行的下一步——照做有受伤风险，不做就完全放弃运动，自己改又不知道改哪里、改到什么程度。现有健身内容的默认前提是「尽量做到位」，而「做不到位怎么办」这一段是空的。

MoveMentor 补的就是这一段：**把「这个动作你做不了」翻译成「这个动作你可以这样做」**，并给出可数、可练、带指导语的版本。

## 它是什么（技术上的定位）

不是一个 App，而是一个**基础组件 + 演示应用**：

| 层 | 内容 | 语言 | 占比 |
| --- | --- | --- | --- |
| 核心引擎 | 动作 DSL 解析器 · 约束校验器 · 翻译求解器 · 计数状态机 · 指导语生成 · 合成姿态源 | **MoonBit** | **2813 行 + 996 行测试；69 条测试全绿** |
| 桥接层 | 会话状态、ESM 导出、两个 JS FFI（Web Speech 语音、高精度计时） | **MoonBit**（`extern "js"`） | 380 行 |
| 演示层 | 页面 UI、骨架渲染、摄像头取流 | HTML/CSS/JS | 635 行，不含任何翻译逻辑 |

**唯一跨语言边界是 132 个浮点数**（33 个关键点 × x/y/z/visibility）和一个 JSON 字符串。视频、图像、模型推理全部留在浏览器侧，引擎在架构上收不到画面。

## 它怎么做（三个可测试的部件）

1. **动作 DSL**：把动作写成一张可读的表——相位、阈值、载荷等级、指导语。`squat` 的「蹲下去」就是 `phase down hip_height_ratio<=0.760`。
2. **约束校验 + 翻译求解**：`load knee=high`（动作要求膝关节负荷 high）与 `allow knee=low`（人群最多接受 low）用**同一个类型**表达，校验退化成一次等级比较。翻译不出来时返回 `Unsupported` 并说明原因，**绝不猜**——这在健康场景里比「看起来差不多」重要得多。
3. **计数状态机**：迟滞带宽 + 最小重复间隔 + dt 钳制 + 低置信帧丢弃，四道防线保证「做了 9 个不会显示成 17 个」。每一道都能被单独测试触发。

## 怎么跑（30 秒）

```bash
moon test --target js              # 69 条测试
moon run cmd/main --target js      # 一键自检：规则校验 + 恒等映射 + 离线演示
moon build --release --target js
node scripts/smoke.mjs             # 验证 MoonBit 产物能被 JS 直接调用
python -m http.server 8000         # 打开 http://localhost:8000/web/
```

演示页面默认走**合成姿态模式**：不需要摄像头、不需要网络，由引擎按当前动作的 DSL 阈值生成确定性骨架，用来验证「翻译 → 计数 → 指导语」整条链路。

## 边界（明确写在文档里）

- 输出的是**降低关节负荷的运动变式**，不构成医疗建议、诊断或康复处方。
- 阈值来自动作生物力学的常识性取舍，**没有做过临床验证**，因此全程不使用「安全」「有效」「适合病人」等表述。
- 规则表当前为 9 个动作 / 4 类人群 / 9 条翻译规则，是「可运行的完整闭环」，不是「覆盖全民的数据库」。

## 演示

三分钟演示脚本见 [`02-演示脚本.md`](02-演示脚本.md)。核心镜头：年轻人做开合跳 → 引擎输出「膝痛版：坐姿抬腿」→ 老人跟着做 → 引擎计次并播报 → 切到轮椅版 → 结尾展示 `moon test` 的绿色输出。
