# MoveMentor · 演示脚本

> 目标：**3 分钟讲完，30 秒内让人看懂**。
> 现场演示依赖摄像头、浏览器环境和网络，黑客松上翻车是常态——所以**离线演示视频是必需品，不是可选项**。

---

## 一、演示前的准备（提前 5 分钟做完）

```bash
cd <仓库根目录>
moon build --release --target js      # 构建引擎产物
python -m http.server 8000            # 起本地 HTTP 服务
```

浏览器打开 `http://localhost:8000/web/`，确认页面右上角出现绿色徽章 **`movementor-engine/0.1.0`**。

- 徽章出现 → 引擎已加载，走主方案。
- 徽章显示「引擎未构建」→ 说明产物路径不对，改跑离线视频（见第四节）。
- **把终端窗口也开着**，最后要展示 `moon test` 的输出。

页面默认 **`姿态来源 = 合成姿态（无需摄像头）`**，这是刻意的：它不依赖摄像头和网络，任何机器上跑出来都一样。

## 二、主脚本（3 分钟，逐镜头）

### 镜头 1｜问题（0:00 – 0:25）

> 「年轻人跟练开合跳，两分钟就出汗了。但同一条视频给到一位膝痛的老人，或者一位轮椅使用者——照做有风险，不做就等于完全放弃运动，自己改又不知道改到哪一步。
> 现有健身内容默认你能做到位。**做不到位怎么办，这一段是空的。**」

画面：页面停在初始状态，源动作 `开合跳`，人群先不动。

### 镜头 2｜翻译（0:25 – 1:05）

把人群切到 **`膝痛 / 老年低冲击人群`**，点「开始翻译」。

> 「引擎告诉我：开合跳对膝关节的负荷等级是 medium，跳落地是 high impact。
> 这位人群的膝关节活动上限是 105 度，而且**不接受任何跳跃冲击**。
> 所以它给出的方案是——**坐姿抬腿**。」

指右侧「为什么这个版本成立」那一栏：

> 「这里每一条都是**约束校验的通过记录**，不是大模型编的一段话。
> `impact` 要求 none，人群允许 none，通过；`knee` 要求 low，人群允许 low，通过。」

### 镜头 3｜计数与播报（1:05 – 1:40）

画面里合成骨架开始做坐姿抬腿，右侧数字开始跳。

> 「注意这个计数——它跑在 MoonBit 的状态机里，不是前端用 setInterval 估的。
> 为了不数错，里面有三道防线：相位迟滞避免在阈值上反复横跳，最小重复间隔滤掉高频噪声，单帧时间差超过 200 毫秒直接钳掉。
> 第四道防线是：关键点可见度低于 0.5 的帧直接丢弃，它宁可说『看不到你的动作』，也不硬猜。」

（语音播报如果开了会念「第三次完成」，可以顺手展示。）

### 镜头 4｜不是一对一，是引擎（1:40 – 2:10）

把人群切到 **`轮椅使用者`**，同一个源动作，点「开始翻译」。

> 「同一个开合跳，给轮椅使用者，出来的是**坐姿双臂上举**。
> 再切到**久坐办公人群**，出来的是**无跳跃开合步**——保留开合节律，只去掉跳跃冲击，工位旁边就能做。」

补一句（**这句必须说**）：

> 「这里所有翻译规则和计次逻辑，**都跑在 MoonBit 里**，不是调 API 转发的。浏览器只负责两件事：拿到关键点，把结果读出来。」

### 镜头 5｜反向 + 边界（2:10 – 2:30）

滚到页面底部的「反向翻译」：

> 「映射表是双向的。从『坐姿抬腿』可以回溯：它是开合跳和深蹲的低冲击替代方案。年轻人动作和老人动作本质是同一张表的两次查询。」

指免责声明：

> 「另外我们全程不说『安全』和『医疗有效』。这是降低关节负荷的变式，不构成医疗建议。」

### 镜头 6｜测试（2:30 – 3:00）

切到终端：

```bash
moon test --target js
```

> 「Total tests: 69, passed: 69, failed: 0.」

```bash
moon run cmd/main --target js
```

让它跑到「每一条翻译规则的约束校验」，九行全绿：

> 「这一屏是自检工具。它把每一条翻译规则都拿约束校验过一遍——**如果谁往规则表里加了一条『膝痛人群去做深蹲到底』这样的坏映射，这一行会立刻变红。**」

收尾：

> 「这就是 MoveMentor：一个 MoonBit 写的动作安全翻译引擎。翻译不出来的时候它会明说『做不到』，而不是猜一个看起来差不多的。」

## 三、现场事故的应对

| 情况 | 处理 |
| --- | --- |
| 本地服务起不来 / 端口被占 | 换端口：`python -m http.server 8080`；或直接放离线视频 |
| 页面白屏、徽章没出现 | 打开控制台看 import 报错；八成是 `_build/js/release/...` 不存在，回终端 `moon build --release --target js` |
| 摄像头模式打不开 | **立刻切回合成姿态模式**，说一句「合成模式是为了让演示不依赖硬件环境」，然后继续。这其实是加分项 |
| 网络断了 | 合成姿态模式 + 命令行自检都完全离线，演示不受影响 |
| `moon test` 意外失败 | 不要现场查，直接放视频，说「本地缓存有问题，这是两分钟前录的完整流程」 |
| 时间被压缩到 1 分钟 | 只讲镜头 2 + 镜头 4 + 镜头 6（翻译 → 三个版本 → 测试全绿） |

## 四、离线演示视频（必备备份）

**录制内容**：完整走一遍第二节的六个镜头，一镜到底，不要剪辑。

**重点录到的画面**：
1. 人群切换时右侧结果的整体替换（开合跳 → 坐姿抬腿 → 坐姿双臂上举 → 无跳跃开合步）；
2. 计数器从 0 跳到非 0 的过程，以及事件行的播报文字；
3. `moon test --target js` 的 `passed: 69, failed: 0`；
4. `moon run cmd/main --target js` 里九行 ✓ 的约束校验。

**录制方式（任选）**：

- Windows：`Win + G` 调出 Xbox Game Bar 录制窗口；
- 或使用 OBS / 系统自带录屏，只录浏览器窗口 + 终端窗口。

**时长控制在 3 分钟以内**。录完自己看一遍，确认字幕/字号在手机屏幕上也看得清。

## 五、一页速记卡（演示前抄在手边）

```
问题：老人/轮椅用户跟练健身视频 → 没有可执行的下一步
方案：MoonBit 动作安全翻译引擎（DSL 规则表 + 约束校验 + 计数状态机）
不是：调 LLM 猜的

演示四步：
  1. 开合跳 + 膝痛人群  → 坐姿抬腿（看「约束校验通过」那一栏）
  2. 切轮椅人群        → 坐姿双臂上举（证明是引擎不是一对一）
  3. 底部反向翻译      → 映射表双向
  4. 终端 moon test    → 69 passed（把「测试质量」变成画面）

必须说的一句：翻译规则和计次逻辑都跑在 MoonBit 里，不是调 API 转发。
必须避的一句：不要说「安全」「医疗有效」「适合病人」。
```
