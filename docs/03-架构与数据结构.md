# MoveMentor · 架构与数据结构

本文档面向**接手代码的人**：三层边界怎么划的、DSL 语法全表、指标定义、计数状态机的四道防线，以及每个设计取舍背后的原因。

---

## 一、三层架构

```
┌───────────────────────────────────────────────────────────────┐
│ 演示层                                                        │
│   web/index.html + style.css + app.js   （浏览器）            │
│   cmd/main/main.mbt                     （命令行）            │
│ 职责：取姿态、画骨架、播语音、打印结果                        │
│ 语言：JS/HTML/CSS 635 行 ｜ MoonBit 217 行                    │
│ 可以整体换掉，不影响翻译逻辑                                  │
└───────────────────────────┬───────────────────────────────────┘
                            │ 进来：Array[Double]，132 个（33 点 × x/y/z/visibility）
                            │ 出去：String（JSON）
┌───────────────────────────▼───────────────────────────────────┐
│ 桥接层 src/bridge/api.mbt（380 行 MoonBit）                   │
│ 职责：会话状态、ESM 导出、把 FFI 包成页面能调的函数           │
│ 唯一接触浏览器的包；两个 JS FFI：语音合成、高精度计时         │
└───────────────────────────┬───────────────────────────────────┘
                            │ 纯函数 + 纯数据结构
┌───────────────────────────▼───────────────────────────────────┐
│ 核心引擎 src/engine/（2813 行生产代码 + 996 行测试）          │
│   types → geometry → metrics → dsl → catalog                  │
│        → translate → counter → speech → synth → json_out      │
│ 不依赖任何宿主：没有浏览器、没有文件、没有网络、没有时钟      │
└───────────────────────────────────────────────────────────────┘
```

### 为什么边界要划在这里

| 取舍 | 原因 |
| --- | --- |
| 跨语言只传 132 个数字 | MediaPipe 的输出天然是「33 点 × 4 个分量」。拍平成数组是最省事、最容易验证的边界；引擎也因此永远拿不到画面 |
| 出口统一是 JSON 字符串 | 页面不需要理解 `MotionSpec` / `Phase` / `Constraint`；加字段不破坏调用方；调试时肉眼可读 |
| 引擎里没有全局状态 | 规则表每次都重新解析（只有 2.7 KB）；出错时「没有隐藏状态」比省那点解析开销重要 |
| 会话状态放在桥接层 | 计次状态机是引擎的一部分，页面刷新一次不该把「已经做了几次」重置掉 |
| 计数器的结构体是值语义 | MoonBit 结构体是值类型：从数组取出 → 本地推进 → 写回。桥接层这 3 行显式表达了所有权，而不是靠引用共享 |

### 换掉依赖要改哪里

- 换姿态模型（不用 MediaPipe）→ 只改 `web/app.js` 里「拍平成 132 个数」的几行；
- 换 UI → 不动引擎；
- 把引擎搬到服务端 → 不动引擎，替换 `src/bridge` 的 FFI 实现（`speak_impl` / `now_ms_impl`）；
- 加一个新动作 / 新人群 → 只改 `catalog.mbt` 里的 DSL 文本；
- 加一个新自由度 → 只在 `metrics.mbt` 加一个分支 + `metric_label` 加一行。

## 二、数据结构

### 2.1 姿态：`PoseFrame`

```moonbit
pub const POSE_POINT_COUNT : Int = 33    // BlazePose 的点数
pub const POSE_STRIDE : Int = 4          // x / y / z / visibility

pub struct Landmark { x : Double; y : Double; z : Double; visibility : Double }

pub struct PoseFrame { points : Array[Double] }
```

`PoseFrame::from_flat(landmarks)` 会校验长度必须等于 132，不合法返回 `None`（而不是 panic 或截断）。

`Joint` 枚举只跟踪 **12 个在正面机位下可靠的点**，每个都带 `mediapipe_index()`：

| Joint | BlazePose 索引 | Joint | BlazePose 索引 |
| --- | --- | --- | --- |
| `LeftShoulder` | 11 | `RightShoulder` | 12 |
| `LeftElbow` | 13 | `RightElbow` | 14 |
| `LeftWrist` | 15 | `RightWrist` | 16 |
| `LeftHip` | 23 | `RightHip` | 24 |
| `LeftKnee` | 25 | `RightKnee` | 26 |
| `LeftAnkle` | 27 | `RightAnkle` | 28 |

其余 21 个点（面部、手部）保留在数组里但不参与计算——它们对动作幅度判断没有贡献，引入只会增加噪声。

### 2.2 指标：唯一的耦合面

**核心边界：动作定义、人群能力、计数状态机三者只通过「指标名」这个字符串耦合。**

```moonbit
pub fn metric_names() -> Array[String]          // 18 个，字典序稳定
pub fn is_known_metric(name : String) -> Bool   // DSL 解析期用它拦拼错的名字
pub fn metric_value(name : String, frame : PoseFrame) -> Double?
pub fn metric_label(name : String) -> String    // 中文短名，供界面与日志
```

指标定义全表（`metrics.mbt`）：

| 指标 | 定义 | 典型读数 | 为什么选它 |
| --- | --- | --- | --- |
| `knee_left/right` | 髋–膝–踝三点夹角 | 站立 ~170°，深蹲 ~90° | 正面下用于判断左右对称性；深度信息弱 |
| `hip_left/right` | 肩–髋–膝三点夹角 | 站立 ~175° | |
| `shoulder_left/right` | 髋–肩–肘三点夹角 | 手臂下垂 ~15° | |
| `elbow_left/right` | 肩–肘–腕三点夹角 | 伸直 ~170° | |
| `trunk_lean` | 肩中点→髋中点 与「正下方」的夹角 | 直立 ~2° | 判断塌腰/前倾 |
| `ankle_span` | 两踝水平距离 ÷ 两肩水平距离 | 并脚 ~0.2，开立 ~2.0 | 归一化，抵消身高与机位远近 |
| `knee_lift_left/right` | 髋–膝竖直距 ÷ 髋–踝竖直距 | 站立 ~0.5，抬平 ~1.0 | 抬腿幅度 |
| `shin_drop_left/right` | 踝–膝竖直距 ÷ 肩髋竖直距 | 坐姿垂腿 ~2.0，抬平 ~0.6 | **坐姿抬腿最稳的读数**：只依赖膝与踝的相对高度 |
| `wrist_above_shoulder_left/right` | 肩–腕竖直距 ÷ 肩髋竖直距 | 手在肩下为负，过头为正 | 举臂类动作 |
| `hip_height_ratio` | 踝中点–髋中点距离 ÷ 踝中点–肩中点距离 | 站立 ~0.78–0.85，下蹲下降 | **正面机位判断深蹲最稳的量** |
| `confidence` | 12 个跟踪点的平均 visibility | 0–1 | 低于阈值整帧作废 |

**两个必须记住的取舍**：

1. **正前方看不到屈膝深度**，所以深蹲类动作不用 `knee_*` 而用 `hip_height_ratio`。改成 30°–45° 侧向机位后，`knee_left` / `knee_right` 会更有信息量，而动作 DSL **无需改动**即可直接引用——这正是「只通过指标名耦合」的收益。
2. `shin_drop_*` 用「躯干长」而不是「髋踝距」做分母，因为它对髋部在画面里的绝对位置不敏感，坐姿动作下更稳。

### 2.3 规则表：`DslProgram`

```moonbit
pub struct DslProgram {
  motions   : Array[MotionSpec]
  audiences : Array[AudienceProfile]
  variants  : Array[VariantRule]
  issues    : Array[DslIssue]      // 解析期诊断，带行号
}

pub struct DslIssue { line : Int; message : String; source_line : String }
```

解析器的设计原则：**收集所有错误，而不是遇到第一个就退出**。错误信息带行号与原始行文本，并且会做语义检查（重名、`variant` 指向不存在的动作、把变式再接一层翻译）。

## 三、DSL 语法全表

规则表的形态：**声明块 + 行式字段**。空行与 `#` 开头的行是注释。块的边界由 `motion` / `audience` / `variant` 三个声明头决定。

### 3.1 `motion <动作 id>`

| 字段 | 语法 | 说明 |
| --- | --- | --- |
| `name` | `name <文本>` | 显示名，**必填**（缺失会报错） |
| `view` | `view front` \| `view side` | 期望机位，只影响文档与 UI 提示 |
| `tag` | `tag <词>` | 标签，**用于兜底替换时的「同族」判定**（共享 tag 越多越同族） |
| `load` | `load <轴>=<等级>` | 载荷等级，等级取值 `none` / `low` / `medium` / `high`；轴是自由词（`impact` / `knee` / `hip` / `spine` / `shoulder` / `balance`） |
| `phase` | `phase <相位 id> [hold=<毫秒>] [<指标><比较><值>]...` | 一个相位；`hold=` 是保持时长，**相位必须在条件成立且维持满 `hold` 后才推进** |
| `cycle` | `cycle <相位 id> <相位 id>...` | 重复动作的循环序列；走完一轮 = 计 1 次。引用了不存在的相位会报错 |
| `cue` | `cue <文本>` | 动作要点，展示给用户 |
| `min_rep_ms` | `min_rep_ms <毫秒>` | 两次计次的最短时间间隔 |
| `hysteresis` | `hysteresis <非负数>` | 相位迟滞带宽 |
| `hold_only_ms` | `hold_only_ms <毫秒>` | 等长动作的目标保持时长；声明了它就**不需要 `phase` + `cycle`**（`brace` 相位除外） |

> **约束**：一个动作必须至少有 `phase` 或 `hold_only_ms` 之一，否则解析期报错。
> 比较运算符只支持 `>=` 与 `<=`（写作 `Ankle_span>=1.60` 或 `trunk_lean<=15`）。

### 3.2 `audience <人群 id>`

| 字段 | 语法 | 说明 |
| --- | --- | --- |
| `name` | `name <文本>` | 显示名，**必填** |
| `limit` | `limit <指标><比较><值>` | 该人群的**能力边界**（角度/比例类）；指标名必须在注册表内，否则报错 |
| `allow` | `allow <轴>=<等级>` | 该人群**可承受的载荷上限** |
| `note` | `note <文本>` | 说明，会出现在文档与界面 |

> **关键未声明语义**：某个轴如果**没有**写 `allow`，就表示「该人群对此没有额外限制」，**不参与校验**。`general` 人群就是靠这一点成为恒等映射。

### 3.3 `variant <源动作> <人群> -> <变式动作>`

| 字段 | 语法 | 说明 |
| --- | --- | --- |
| `reason` | `reason <文本>` | 为什么这么翻译。会原样显示在界面上，**必须是人话** |

> 变式动作必须是已声明的 `motion`；被用作 target 的 motion 不允许再被当作源动作（避免翻译链）。`->` 两侧的 token 数量会被检查。

### 3.4 完整示例

```
motion squat
name 徒手深蹲
view front
tag strength
tag standing
load impact=low
load knee=high
phase down hold=200 hip_height_ratio<=0.760
phase up hold=200 hip_height_ratio>=0.790
cycle down up
min_rep_ms 700
hysteresis 0.010
cue 髋部向后向下坐，膝盖尽量不超过脚尖

audience elderly_knee_pain
name 膝痛 / 老年低冲击人群
limit knee_left<=105
limit ankle_span<=1.20
allow impact=none
allow knee=low

variant squat elderly_knee_pain -> chair_squat
reason 保留蹲起模式，限制下蹲幅度并提供椅背支撑，把膝负荷降到低位
```

## 四、翻译求解

### 4.1 一种约束类型，两处使用

```moonbit
pub enum Compare { AtLeast; AtMost }

pub struct Constraint {
  metric : String      // 或载荷轴名
  cmp    : Compare
  value  : Double      // 或载荷等级 rank
}
```

- 动作侧：`load knee=high` → 语义是「膝关节负荷**至少**会到 high」；
- 人群侧：`allow knee=low` → 语义是「膝关节负荷**最多**能到 low」。

于是校验退化成一次等级比较：

```moonbit
pub fn conflicts(target : Constraint, limit : Constraint) -> Bool {
  match (target.cmp, limit.cmp) {
    (AtLeast, AtMost) => target.value > limit.value   // 严重
    (AtMost,  AtLeast) => target.value < limit.value  // 方向相反也不成立
    _ => false                                        // 同向永不冲突
  }
}
```

### 4.2 三种结果，其中一种是「明确拒绝」

| 结果 | 触发条件 |
| --- | --- |
| `Translated` | 规则表里有（动作，人群）的专属变式，且变式通过 `validate` |
| `Substituted` | 没有专属变式，但存在**至少共享一个 tag** 且能过校验的替代动作 |
| `Unsupported` | 以上都不成立；或规则表本身不自洽（变式仍然违反人群边界、`variant` 指向不存在的动作） |

`find_substitute` 的打分：共享 tag 数最多者胜；**并列时取声明在前的**——保证同一个输入永远得到同一个输出（确定性）。

### 4.3 校验证据不是话术

`build_checks` 生成的中文说明，每一条都是**真的被比较过的量**：

```
载荷 impact：动作「none」≤ 人群上限「none」
载荷 knee：动作「low」≤ 人群上限「low」
指标 knee_left（左膝夹角）：动作要求 ≤105，人群边界 ≤105，无冲突
人群边界共 6 条、载荷上限 3 条，本变式全部通过
原动作：开合跳，共 2 个相位
```

这些字符串原样进入界面「为什么这个版本成立」那一栏。界面不做二次加工，因此**不存在「界面说的是 A、引擎算的是 B」的可能**。

## 五、计数状态机的四道防线

```
每帧：
  1. 计算 confidence = 12 个跟踪点的平均 visibility
     若 < 0.5 → 整帧作废，返回 LowConfidence，不推进任何状态
  2. delta = now - last，且 clamp 到 [0, 200] ms        ← 防线 3：dt 钳制
  3. 若是等长动作 → update_hold
     否则          → update_reps
```

### 防线 1：相位迟滞 `hysteresis`

进入相位用**严格阈值**，维持相位用**放宽阈值**（带宽 = `hysteresis`）。

```moonbit
fn phase_satisfied(phase, frame, hysteresis, relaxed) -> Bool
```

以深蹲为例，`hip_height_ratio` 在 0.760 附近抖动时：

- `< 0.760` → 判定进入 `down`；
- 升到 `0.765` → 落在 `[0.760, 0.790]` 滞回带里，**保持 `down` 不变，也不给 dwell 累加时间**；
- `>= 0.790` → 才判定回到 `up`。

「保持相位但不累加 dwell」这一步是关键：既不会因为抖动回退相位，也不会因为抖动凑满保持时长。

### 防线 2：最小重复间隔 `min_rep_ms`

```moonbit
if now_ms - self.last_rep_ms >= self.plan.min_rep_ms { ... 计次 ... }
```

初始化时 `last_rep_ms = 0 - min_rep_ms`，保证**第一次重复一定被计入**，而不是被最小间隔在启动瞬间误杀。

### 防线 3：dt 钳制 `MAX_DELTA_MS = 200`

切标签页、掉帧、GC 停顿都会产生一个巨大的 `now - last`。不钳制的话，一次「保持时间」会被一次性灌进几秒。上限 200 ms 相当于「一帧最多承认 200 毫秒」。

### 防线 4：低置信帧丢弃 `MIN_CONFIDENCE = 0.5`

看不清就不猜：整帧作废并 `armed = false`。**宁可漏计，不可误计**——漏计只是数字少了，误计会让用户怀疑整个系统。

### 计次语义

```
一个重复动作的计次 = 沿 cycle 序列走完一整轮
每个相位必须：条件成立 且 连续维持 >= phase.hold_ms
```

「维持」要求是刻意的：它让计数对单帧噪声免疫，代价是动作必须到位一小段时间（合成姿态源的 duty cycle 就按这个设计）。

```moonbit
pub fn api_now_ms() -> Int { now_ms_impl() }

  #| function() {
  #|   if (typeof performance !== "undefined" && typeof performance.now === "function") {
  #|     return Math.floor(performance.now());
  #|   }
  #|   return Date.now() | 0;
  #| }
```

## 七、合成姿态源：为什么它是必需品

现场演示依赖摄像头、浏览器和网络——这三样在黑客松上翻车是常态。`synth.mbt` 提供了一个**确定性的假骨架**：

```moonbit
pub enum Archetype { SeatedLegLift; StandingBilateral; Squat; SeatedArmRaise; LeanHold }

pub fn synth_params(archetype : Archetype, plan : MotionSpec, s : Double) -> SkeletonParams
pub fn synth_frame(plan : MotionSpec, now_ms : Int) -> PoseFrame
pub fn archetype_of(plan : MotionSpec) -> Archetype
pub fn synth_period_ms(plan : MotionSpec) -> Int
```

工作方式：

1. 从动作的 DSL 阈值反推该动作的「起始位」与「做到位」两组骨架参数（`s = 0` 与 `s = 1`）；
2. 用**梯形波**在两者之间插值，占空比 20% 上升 / 30% 保持 / 20% 下降 / 30% 保持——「保持」段正是为了让相位 `hold_ms` 能被满足；
3. 对阈值做**过冲**处理，保证合成出的数值确实能跨过 DSL 里声明的阈值；
4. 周期 `synth_period_ms` 由 DSL 的 `hold_ms` 与 `min_rep_ms` 共同决定。

因此 `moon run cmd/main` 里 12 秒合成姿态跑出 6 次坐姿抬腿是**确定值**，可以直接写进回归断言。

**它不是 mock，是夹具**：它让「翻译 → 计数 → 指导语」整条链路在任何机器上、任何网络条件下都能被完整验证。
